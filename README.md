# Acan

Acan 是一个以电子书柜形式整理和浏览杂志影像的响应式静态网站。

网站采用“同一份刊物数据、同一个杂志盒子、两种展示外壳”的结构：默认资料站视图提供
稳定的网格浏览，房间视图提供茶几场景交互。两种入口打开后都进入同一个真实翻页阅读器。
项目使用原生 HTML、CSS 和 JavaScript，站点运行时没有第三方依赖。

完整第一视角房间、墙面商务海报、电脑视频和日历日常图的规划见 [TODO.md](TODO.md)。

## 功能

- 资料站与房间场景一键切换，共用同一批杂志卡片
- 响应式电子书柜，根据屏幕宽度自动调整每行数量
- 杂志按日期从早到晚排列，封面下方显示标题和日期
- 桌面端双页 3D 翻页，窄屏自动切换单页阅读
- 支持点击页边、左右拖动、键盘方向键翻页
- 支持封面、封底合拢状态与动态左右纸张厚度
- 底部快速进度条可直接跳转，并同步更新左右剩余页数
- 双击杂志或点击“放大”切换阅读尺寸，`Esc` 返回书柜

## 本地预览

双击根目录中的 `start.bat`，浏览器会自动打开：

```text
http://localhost:5500/
```

也可以手动启动：

```bash
node web/server.js
```

当前页面入口不依赖 ES module 或运行时 `fetch`，因此直接打开 `web/index.html` 也能浏览；
推荐使用本地服务器，以获得与部署环境一致的路径和缓存行为。

## 素材格式

每本杂志的原始素材放在：

```text
web/data/magazine/<YYYYMMDD 名称>/
```

文件夹名必须以日期开头，日期用于确定书柜顺序。

| 文件 | 用途 |
| --- | --- |
| `1.jpg` | 主封面，也是书柜封面 |
| `2.jpg` | 可选二封 |
| `名称 (1).jpg`、`名称 (2).jpg` | 正片，按括号中的数字排序 |
| `幕后1.jpg` 等其他名称 | 花絮，由构建脚本自动归组 |
| `<杂志标题>.txt` | 刊物标题及文字信息 |

文字文件使用以下四行格式：

```text
标题：CHIC八月大片
时间：2026.08.12
简介：这个夏天，她想带着……
备注：实体刊，AB封，6张小卡
```

`.txt` 文件名作为书柜上的杂志标题。文字内容支持 `[文字](网址)` 和直接书写
`https://...` 两种链接格式。

## 构建图片

原图体积较大，不直接进入仓库。构建脚本使用 `sharp` 生成适合网页读取的 WebP、
缩略封面和 `meta.json`。

首次使用：

```bash
cd web/tools
npm install
npm run build
```

只重新构建某一本杂志：

```bash
node build-magazines.js CHIC
```

生成结果位于 `web/data/magazines/`。原始目录 `web/data/magazine/` 已被 `.gitignore`
排除。

## 添加或更新杂志

1. 按素材格式把原图和 `.txt` 放入 `web/data/magazine/`。
2. 运行图片构建脚本。
3. 检查生成目录中的 `meta.json` 和 `skipped` 字段。
4. 在 `web/data/catalog.js` 中新增或更新对应刊物；如有真实封底，填写 `backCover`。
5. 启动网站，检查资料站、房间视图、翻页数量和进度条。

当前页面只读取 `web/data/catalog.js` 中的 `window.ACAN_CATALOG`。资料站、房间场景、
封面和翻页内页都引用同一份配置；新杂志不需要修改 `app.js` 或页面结构。

## 图源

每本刊物在 `web/data/catalog.js` 中使用同一个数据对象：

```js
{
  id, title, date, timestamp,
  cover,       // 资料站、房间场景和阅读器封面共同使用
  pages,       // 按翻页顺序排列
  backCover,   // 可选；为空时生成默认封底
}
```

默认路径指向 `web/data/magazines/` 下的 WebP 构建产物。以后需要切换图片、规格或 CDN，
只需修改这份数据配置，不需要改资料站、房间场景或阅读器代码。

## 已知素材问题

构建时无法处理的文件会打印到终端，并写入对应 `meta.json` 的 `skipped` 字段。

- `20260811CHIC/大片.mp4`：视频暂未接入站点
- `20260811CHIC/预告.jpg`：文件实际使用 HEIF 编码，需要重新导出为标准 JPG
- `20260811CHIC/CHIC (3).jpg`：源文件缺失，编号从 2 跳到 4

大图查看器当前读取 WebP 构建产物，而不是约 740 MB 的原始素材。若未来部署需要更高
清晰度，建议单独生成高清档或接入对象存储/CDN，而不是把全部原图提交到仓库。

## 技术说明

- 前端：原生 HTML、CSS、JavaScript
- 运行时依赖：无
- 本地服务器：Node.js 内置 `http` 模块
- 图片构建：Node.js + `sharp`
- Python/uv 文件目前只是仓库骨架，未参与网站运行
